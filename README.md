# 청운대학교 야구부 웹사이트

정적 HTML/CSS/JavaScript 웹사이트입니다. `main.html`이 최상위 홈 파일이고 GitHub Pages 진입을 위한 `index.html`은 이 페이지로 연결합니다. 각 페이지 폴더에는 폴더명과 일치하는 HTML, CSS, JS 파일이 있습니다. 예: `admin/admin.html`, `admin/admin-style.css`, `admin/admin.js`. Java는 브라우저용 언어가 아니므로 요청의 `.java` 표기는 `.js`로 해석했습니다.

## 실행과 배포

1. **로컬 테스트:** Node.js 20 이상을 설치한 뒤 프로젝트 폴더에서 아래 명령을 실행합니다.

   ```bash
   cd functions
   npm install
   cd ..
   node local-server.js
   ```

   브라우저에서 `http://localhost:5500/main.html`을 열면 협회 경기 URL을 입력해 기록을 가져올 수 있습니다. VS Code의 **Go Live는 종료**하고 이 서버를 실행하세요. Go Live가 같은 5500 포트를 사용 중이면 서버가 시작되지 않습니다. 기존 8000 포트가 필요하면 macOS/Linux에서 `CWU_PORT=8000 node local-server.js`, Windows PowerShell에서 `$env:CWU_PORT=8000; node local-server.js`로 실행할 수 있습니다. Go Live나 `python3 -m http.server`는 경기 URL 가져오기 API를 제공하지 않습니다. `file://`에서도 ES 모듈이 제한됩니다.

2. **GitHub Pages 배포:** 이 폴더 전체를 GitHub 저장소 루트에 올리고 Settings → Pages에서 `main` 브랜치 `/ (root)`를 게시합니다. 배포된 페이지의 URL 가져오기는 아래 Firebase 함수가 필요합니다.
3. Firebase 콘솔에서 Firestore와 Storage를 활성화합니다. Firebase Authentication은 사용하지 않습니다.
4. Firebase CLI에서 `firebase deploy --only firestore:rules,storage`를 실행해 이 프로젝트에 포함된 규칙을 배포합니다. 기존 규칙이 배포된 상태라면 관리자 화면은 열려도 저장이 거절됩니다.
5. 관리자 화면에서 `cwutest`를 입력합니다. 같은 브라우저 탭에서 로그아웃하거나 탭을 닫을 때까지 관리자 화면을 사용할 수 있습니다. 선수·경기 정보는 Firestore에, 갤러리 사진은 Storage에 저장됩니다. 선수 사진은 로컬 서버가 프로젝트의 `image/` 폴더에 저장하며 메인 사진은 직접 복사합니다.
6. GitHub Pages에서 협회 URL만으로 경기와 선수 기록을 가져오려면 별도 `previewKbsaGame` 함수가 필요합니다. 로컬 테스트에는 필요하지 않습니다. 프로젝트 루트에서 `cd functions && npm install && cd .. && firebase deploy --only functions`를 실행하세요. 함수가 없다면 협회 `record_detail` 페이지를 브라우저에서 **HTML만 저장**한 후 관리자 → 경기 → **HTML 파일에서 불러오기**를 사용하세요. 이 방식은 함수 없이도 경기와 선수 기록을 함께 미리보고 Firestore에 등록합니다. 기존 경기·선수 수동 등록과 엑셀 명단 등록도 그대로 동작합니다.

첨부된 CWU 로고는 `assets/cwu-logo.png`에 두었고, 공통 색상은 `common/common-style.css`에서 바꿀 수 있습니다. 선수 화면은 포지션 버튼으로 필터링하며 선수 카드와 관리자 등록 목록은 배번 숫자 오름차순(0 포함)으로 표시합니다.

### 메인·선수 JPG 파일\n+

메인 사진은 **직접** `image/main/main.jpg`에 복사하고 GitHub에 올립니다. 메인 화면은 사진이 가로 영역을 빈 공간 없이 채우며, 원본 비율에 따라 가장자리가 잘릴 수 있습니다. 관리자에서 메인 사진을 수정하는 메뉴는 없습니다. 선수 사진은 `image/players/{연도}/{배번}.jpg`로 저장합니다. 예를 들어 2026년 7번 선수는 `image/players/2026/7.jpg`입니다. 기존 선수 Storage 사진 URL은 새 로컬 파일이 없을 때만 표시합니다. 관리자에서 선수 사진을 업로드하려면 **Go Live가 아닌 `node local-server.js`**로 접속해야 하며, GitHub Pages에서는 파일 업로드가 불가능합니다. 배포하려면 추가된 JPG 파일을 GitHub에 함께 커밋하세요. 경로를 고정해 같은 파일을 덮어쓰지만, 폴더 구조 자체가 파일 크기를 줄이는 것은 아닙니다. 기존 Storage 파일은 자동 삭제되지 않으므로 로컬 선수 사진 표시를 확인한 뒤 별도로 정리해야 Storage 사용량이 줄어듭니다. 갤러리 사진은 계속 Storage에 저장됩니다.

## 데이터 구조

- `players/{season}-{uniformNumber}`: name, number, year, position, height, weight, batsThrows, highSchool, grade (기존 photoUrl은 로컬 사진이 없을 때만 사용)
- `games/kbsa-{game_idx}` 또는 임의 UUID: date (`YYYY-MM-DD`), time, competition, venue, opponent, status, cwuScore, opponentScore, innings (`[{cwu,opponent}]`), scoreboard (`{cwu:{r,h,e,b},opponent:{r,h,e,b}}`), sourceGameId, sourceUrl
- `playerGameStats/{gameId}_{playerId}`: gameId, playerId, playerName, position, atBats, hits, rbi, runs, homeRuns, inningsPitched, inningsOuts, strikeouts
- `events/{UUID}`: date, title, description
- `photos/{UUID}`: date, caption, gameId 또는 eventId, url

경기 링크는 `results/results.html#<game document ID>`입니다. 같은 ID를 선수 기록과 사진의 `gameId`에 사용합니다. 관리자 → 선수 → 선수 엑셀 일괄 등록에서 제공한 `2026년 청운대.xls` 파일을 변환 없이 선택하고 시즌 연도 2026을 확인한 뒤 명단 미리보기와 일괄 등록을 누릅니다. `.xls`, `.xlsx`, `.csv`를 지원하며 `성명, 학년, 포지션, 백넘버, 투타, 신장, 체중, 출신교` 열을 자동으로 연결합니다. CSV는 UTF-8을 권장합니다. 명단 파일의 `미지정` 포지션과 배번 `0`을 그대로 저장합니다. 동일한 연도·배번은 명단 필드만 갱신하고 기존 사진과 선수 기록을 보존합니다. 엑셀 파서는 업로드 시에만 로드합니다.

경기 결과 상단 메뉴의 하위 항목은 등록된 경기의 대회명으로 구성됩니다. 대회 메뉴는 `results/results.html?competition=<대회명>`으로 연결되고 경기 결과 화면의 대회 선택과 연동됩니다. 새 대회를 등록한 뒤 페이지를 새로고침하면 메뉴에 반영됩니다.

이미 등록한 경기의 H/E/B를 채우려면 수정된 프로젝트의 `node local-server.js`를 다시 실행한 뒤 관리자에서 같은 경기 URL을 다시 가져와 저장하세요. `games/kbsa-{game_idx}` 문서에 `scoreboard`가 갱신됩니다. 협회 HTML의 이닝 점수는 `td`, R/H/E/B 합계는 `th`이므로 두 열을 함께 판독합니다. 가져오기 미리보기에서 양 팀의 R/H/E/B를 확인할 수 있고, 합계가 빠진 이전 버전의 함수 응답은 저장하지 않습니다. GitHub Pages에서 URL로 가져올 때는 수정된 Firebase 함수를 다시 배포해야 하며, 배포 전에는 HTML 파일 가져오기를 사용할 수 있습니다.

로컬 서버가 R/H/E/B를 보내지 않는다고 나오면 기존 `node local-server.js`가 실행 중인 터미널에서 `Ctrl+C`로 종료하고, ZIP을 덮어쓴 실제 `cwu-baseball` 폴더에서 다시 실행하세요. Go Live를 쓰는 탭이나 이전 서버의 탭 대신 새 서버 주소(`http://localhost:5500/main.html`)를 열고 새로고침합니다. 새 로컬 서버는 이후 `functions/kbsa-parser.js` 변경분을 다음 가져오기 요청부터 다시 읽습니다.

## 운영상 주의

`cwutest` 확인은 브라우저 화면에서만 이뤄집니다. **Firestore와 Storage는 정해진 컬렉션·경로에 대해 공개 쓰기를 허용하므로, 누구나 비밀번호를 우회하여 데이터를 수정·삭제하거나 사진을 올릴 수 있습니다.** GitHub에 공개하면 비밀번호 자체도 소스에서 보입니다. 이는 요청한 “Firebase 로그인 없이 브라우저에서 DB를 직접 수정”하는 방식의 기술적 한계입니다. 공개 운영용으로 안전하게 만들려면 Firebase Authentication 또는 서버에서 검증하는 인증이 필요합니다. PC 제한도 화면 크기/포인터 기준의 UI 제한이며 기기 보안 검증이 아닙니다.

협회 `box_score` 또는 `record_detail` URL을 입력하면 배포된 함수가 같은 `game_idx`의 `record_detail`을 읽어 경기 날짜·점수·이닝과 청운대 타자·투수 기록을 반환합니다. 관리자는 미리보기에서 등록 선수 연결을 확인하고 저장합니다. 이름과 배번이 동시에 일치하는 같은 연도 선수만 자동 연결하며, 연결되지 않은 기록은 직접 선수를 선택하거나 제외해야 합니다. 같은 경기를 다시 저장하면 같은 경기·선수 문서를 갱신합니다. 39152 경기의 HTML로 파서를 검증했지만 원본 구조가 달라지면 가져오기에 실패할 수 있습니다. 화면에 `internal` 오류가 보이던 것은 이 프로젝트에서 함수를 호출하는 현재 주소가 404를 반환해 해당 주소에서 함수를 찾지 못했기 때문입니다. 배포 후에도 오류가 나면 Firebase Functions 로그를 확인하세요. 원본 기록과 미리보기를 대조하고 사이트의 데이터 이용 조건을 확인하세요.

날짜별 5개 경기는 Firestore 데이터를 읽어 클라이언트에서 필터링합니다. 데이터가 대량으로 쌓이면 범위 인덱스 쿼리와 페이지네이션으로 전환하세요. 갤러리 사진은 장당 250KB 이하 JPG이며 여러 장을 선택할 수 있습니다. 목록에서는 lazy loading합니다.

### 협회 기록 가져오기 데이터

협회 기록 HTML 또는 로컬 URL 가져오기를 통해 저장한 `games/{gameId}`에는 `lineup`(타순, 교체 출전 순서)과 `pitchingLineup`이 포함됩니다. `playerGameStats/{gameId}_{playerId}`에는 역할별 `batting`과 `pitching` 객체를 별도로 저장합니다. 한 선수가 양쪽에 출전하면 두 객체가 같은 문서에 저장됩니다. `pitching`에는 등판, 결과, 승패, 이닝, 타자, 투구수, 상대 타수, 피안타, 피홈런, 4사구, 삼진, 실점, 자책, 원본 평균자책점이 들어갑니다. 수동으로 입력한 기존 기록은 가능한 항목만 표시됩니다. 이전에 가져온 경기는 관리자에서 같은 링크를 다시 가져와 등록하면 새 항목과 라인업이 채워집니다.

### 이전 소속 선수 기록

관리자 → **이전 소속 기록**에서 협회 경기기록 URL 또는 저장한 HTML을 불러옵니다. 원본 경기의 양 팀 선수 기록을 모두 표로 확인한 뒤, 모든 소속 학교의 각 선수 행에서 현재 명단 선수를 직접 선택하고 한 번에 저장합니다. 이름이 같은 행은 강조만 하며 자동 선택하지 않습니다. 원본 이름이나 학교가 달라도 자동 연결하지 않습니다. 연결하지 않은 행은 저장하지 않습니다. `playerHistoryStats/{kbsa-경기ID}_{선수ID}`에 원본 소속팀, 경기 날짜·대회·상대팀과 타자/투수 기록이 저장됩니다. 이 기록은 청운대 경기 일정·결과나 청운대 시즌 합계에는 들어가지 않고 선수 상세의 **전체 기록**과 **기간 선택**에 포함되며, **청운대 기록**에는 포함되지 않습니다. 등록 목록의 날짜·경기를 펼치면 선수별 기록을 수정·삭제할 수 있습니다. 최신 `common/firebase.rules`를 Firestore에 배포해야 새 컬렉션을 사용할 수 있습니다. URL 가져오기는 로컬에서 `node local-server.js`가 필요하며, 배포 사이트에서는 최신 Firebase 함수를 배포하거나 HTML 파일을 선택할 수 있습니다.

사진 등록은 등록된 **경기 또는 기타 일정** 중 하나를 반드시 선택합니다. 훈련 사진은 먼저 기타 일정으로 훈련을 등록한 뒤 해당 일정을 선택하세요. 선택한 일정의 날짜가 자동 입력됩니다. 갤러리 JPG는 여러 장을 한 번에 선택할 수 있으며 각 파일은 250KB 이하이어야 합니다. 기타 일정 사진은 갤러리에만 표시됩니다. 선수 경기 기록은 경기 가져오기에서만 생성합니다. 별도의 관리자 기록 탭 없이 **경기 → 등록 목록 → 선수 기록 보기**에서 선수별로 수정·삭제할 수 있습니다. 선수 상세는 전체/청운대/기간 범위를 선택할 수 있으며 투수는 투수 기록, 다른 포지션은 타자 기록이 기본으로 열립니다. 사진 용량 제한을 Storage에서도 적용하려면 `common/storage.rules`를 배포해야 합니다.

이전 소속 경기 URL을 가져올 때 `청운대 경기로 확인되지 않았습니다`가 나오면 실행 중인 구버전 로컬 서버를 Ctrl+C로 종료하고 새 프로젝트 폴더에서 `node local-server.js`를 다시 실행하세요. 기존 Firebase 함수도 최신 코드로 재배포해야 합니다. HTML 파일 가져오기는 서버 함수 없이 사용할 수 있습니다.

상단 선수 정보 메뉴의 하단 바로가기는 투수·내야수·외야수·포수로 연결됩니다. 선수 페이지는 URL의 `?position=` 값을 읽어 목록을 즉시 필터링하며, 경기 일정과 기타에는 하단 메뉴가 없습니다.

모바일에서는 내비게이션이 밝은 서랍형 패널로 열리고 바깥 영역·닫기 버튼·Esc로 닫을 수 있습니다. 선수 상세의 최근 경기 기록은 모바일에서 항목별 카드로 표시하며, 메인 사진 네모는 모바일에서 최대 320×300px로 줄이고 사진과 제목 영역을 나누어 전체 이미지를 표시합니다.

선수 상세 팝업은 기록 합계·최근 5경기·대회별 기록을 선택하여 한 영역씩 보여주므로 세 화면이 세로로 이어지지 않습니다.

모바일 메인 사진은 작은 가로 3:2 카드에 PC와 같은 사진 위 제목 스타일로 표시합니다. 모바일 헤더는 메뉴 버튼을 왼쪽, 브랜드를 가운데에 놓습니다. 선수 상세는 전체·청운대·기간 선택 기록을 확인할 수 있으며 전체 기록의 합계 아래에서 연도별 합계를 펼쳐 볼 수 있습니다.

모바일 메인 사진 카드는 아래 경기 박스와 같은 폭으로 표시하고 제목은 사진 아래쪽에 작은 여백으로 겹칩니다.


## 투수 승·패·세이브·홀드 업데이트

관리자 ‘경기’ 또는 ‘이전 소속 기록’에서 ‘투수 승·패·세이브·홀드 일괄 업데이트’를 이용합니다. ‘등록된 경기 원본 다시 읽기’는 연결된 원본 경기별로 다시 읽고 기존 투수 문서의 네 항목만 갱신합니다. 원본 URL 읽기가 어려우면 ‘저장한 경기 HTML 여러 개’에서 원본 전체 HTML을 복수 선택하고 ‘선택한 HTML로 일괄 업데이트’를 누릅니다. 기존 선수 연결·타자 기록·다른 투수 수치는 유지하며 실패/매칭 불확실 기록은 변경하지 않고 처리 결과에 표시합니다. 원본 게임 ID와 날짜, 원본 선수 이름·배번(이전 소속은 팀까지)을 확인합니다.

선수 상세의 경기별·전체·연도별·대회별 투수 기록과 경기 결과에는 승·패·세이브·홀드를 표시합니다. 해당 경기 결과 표시로 계산하며 원본의 누적 승패는 합산하지 않습니다. 미확인 항목은 0과 구분합니다. 로컬 사용 시 새 파일 교체 후 `node local-server.js`를 재시작합니다.
